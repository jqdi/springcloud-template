## 2. 核心链路

### 2.1 路由决策流程

```
请求进入 Gateway
  → DeveloperLoadbalancer.choose(Request)
    → 从 RequestDataContext 提取 HttpHeaders
    → 按 developer.headers 配置取请求头值 → developerList
    → supplier.get(request) 取全量 ServiceInstance
    → servicePriorityPolicyManager.serverOrder(instance, developerList) 给每个实例打分
    → Collectors.groupingBy(serverOrder) 分组
    → min(order) 取最高优先级组
    → 组内 RoundRobin 轮询
  → Response<ServiceInstance>
```

关键代码: [DeveloperLoadbalancer.choose() L44-L68](file:///d:/code/springcloud-template/gateway/src/main/java/com/company/gateway/developer/DeveloperLoadbalancer.java#L44-L68)

### 2.2 策略链匹配流程

```
ServicePriorityPolicyManager.serverOrder(instance, developerList)
  → 按 getOrder() 排序的策略链遍历
  → 第一个 support(instance, developerList)=true 的策略给出 serverOrder
  → 无命中 → DefaultServicePriorityPolicy.serverOrder (兜底)
```

关键代码: [ServicePriorityPolicyManager L28-L41](file:///d:/code/springcloud-template/gateway/src/main/java/com/company/gateway/developer/policy/ServicePriorityPolicyManager.java#L28-L41)

## 3. 策略实现矩阵

| 策略类 | getOrder | serverOrder | support 条件 | 语义 |
|---|---|---|---|---|
| DeveloperSelfPriorityPolicy | 100 | 1000 | `metadata.developer` 在 developerList 中 | 开发者自己的本地实例（最高优先） |
| OnLineServicePriorityPolicy | 200 | 2000 | `metadata.developer_route_tag` 含 `ONLINE` | 环境在线服务 |
| DefaultServicePriorityPolicy | MAX | 10000 | 永远 true | 兜底（无 metadata 的普通实例） |
| OtherDeveloperPriorityPolicy | 300 | 20000 | `metadata.developer` 存在但不在 developerList 中 | 其他开发者的本地实例（最低优先） |

## 5. 灰度路由改造扩展点

### 5.1 可直接复用的基础设施

| 设施 | developer 现状 | 灰度可复用性 |
|---|---|---|
| 自定义 LB 继承 RoundRobinLoadBalancer | DeveloperLoadbalancer | 完全复用模式 |
| `@LoadBalancerClients` + `@ConditionalOnProperty` | DeveloperRouteAutoConfiguration | 完全复用模式 |
| 请求头提取 → 标识列表 | developerHeaders 配置 + headers 解析 | 完全复用 |
| metadata 读取 | `serviceInstance.getMetadata().get(...)` | 完全复用 |
| 分组取最高 + 组内轮询算法 | serverOrder 分组 + min(order) | 规则灰度可复用 |

### 5.2 需新增的能力（业界三层架构对照）

| 层 | developer 现状 | 灰度需要 | 改造点 |
|---|---|---|---|
| 第1层 流量染色 | 无（请求头已带标识） | Gateway GlobalFilter 按规则打标 | 新建 GrayDyeFilter |
| 第2层 标记透传 | 无（仅网关层） | Feign Interceptor 全链路透传 | 新建 GrayFeignInterceptor，复用 HttpContextFilter |
| 第3层 智能路由 | 有（分组取最高） | 增加泳道隔离 fallback + 权重选择 | 新建 GrayLoadbalancer + GrayRuleStrategy + GrayWeightStrategy |

### 5.3 与 developer 模块的共存约束

- `@LoadBalancerClients(defaultConfiguration=...)` 同一服务只能有一个生效
- 必须通过 `@ConditionalOnProperty` 互斥：`developer.enabled` 与 `gray.enabled` 不能同时 true
- 环境分工：dev/test/pre 用 developer，prod 用 gray

## 7. 风险热点

- `@LoadBalancerClients` 冲突：developer 与 gray 同时启用会 Bean 报错 → 严格互斥
- 权重灰度算法：现有分组取最高不兼容加权随机 → 需独立 GrayWeightStrategy
- Feign 透传丢失：跨服务调用灰度标识不传递 → 必须 GrayFeignInterceptor
- metadata 缺失：所有实例无 version/weight → 灰度退化为轮询（需 fallback 兜底）
